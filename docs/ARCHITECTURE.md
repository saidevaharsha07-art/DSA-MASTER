# Architecture

The DSA CRACKER relies on a **Universal Content Engine** instead of hardcoded React components.

## Core Concepts

### 1. Single Source of Truth
Educational content (like explanations, quizzes, complexity analyses) is never written directly inside a `.tsx` file. Instead, it lives as strongly-typed TypeScript objects in `src/content`. 

**Why TypeScript instead of JSON/Markdown?**
- First-class type safety via Zod validation.
- Allows inline template strings and code block multi-lining easily.
- Instant module resolution and autocomplete in IDEs.
- Allows exporting specific fragments natively.

### 2. Hybrid Registry System
To maintain instant runtime lookups without Webpack filesystem scanning hacks, we use a hybrid registry:
- Every folder has an `index.ts` barrel file exporting its contents.
- `src/registry/index.ts` imports these barrels and maps them by `ID`.
- This ensures perfect tree-shaking and immediate startup times.

### 3. Engines
- **Curriculum Engine**: Handles all domain queries (e.g., "Get all problems for this pattern").
- **Metadata Engine**: Aggregates global statistics (total problems, company coverage, etc.).

### 4. Build-Time Indexing
To keep the application fast, we generate heavy structures during build time:
- `search-index.json`: Used by Fuse.js in the Command Palette.
- `knowledgeGraph.json`: Used by visualization layers.
These are generated by `npm run build:indexes` and output to `/public`.

### Data Flow
`src/content/*.ts` -> `src/registry/index.ts` -> `src/engines/curriculum` -> `React Server/Client Components`.
